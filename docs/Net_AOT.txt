1. Actívalo en el archivo de tu proyecto (.csproj)
Para decirle a .NET que quieres usar Native AOT, solo tienes que abrir el archivo .csproj de tu aplicación (por ejemplo, una API Web de tipo Minimal API o una app de Consola) y añadir la etiqueta <PublishAot>true</PublishAot> dentro del bloque principal [C]:

    <Nullable>enable</Nullable>

    <PublishAot>true</PublishAot>
  </PropertyGroup>
</Project>

2. Compila "a mano" desde la terminal
Una vez añadida esa línea, abres tu terminal (puede ser la de Windows o tu nueva terminal de Linux) en la carpeta del proyecto y ejecutas el comando de publicación [C]:

dotnet publish -c Release

¿Qué ocurre bajo el capó en ese momento?
El SDK iniciará un proceso especial [C]:
1. Análisis de código (Trimming): El compilador escaneará tu código "a mano" y borrará absolutamente todo lo que no uses de las librerías de Microsoft para que el archivo final no pese cientos de megabytes.
2. Compilación Nativa: Invocará las herramientas del sistema (como ILCompiler) para traducir tu C# intermedio a binario puro [C].
3. El resultado: En la carpeta de salida (/bin/Release/net8.0/[sistema]/publish/) no encontrarás archivos .dll. Encontrarás un único archivo ejecutable nativo (un .exe en Windows o un archivo ejecutable sin extensión en Linux) [C].
Un detalle importante (El choque con la POO dinámica)
Como eres un desarrollador avanzado, debes saber que el Native AOT te impone una pequeña restricción: no se lleva bien con la reflexión dinámica extrema (como hacer un Assembly.Load() en tiempo de ejecución o serializaciones JSON que dependan de inspeccionar objetos al vuelo). Como el compilador necesita saber antes de compilar qué se va a usar para poder optimizarlo, si usas mucha reflexión, el propio compilador te avisará con warnings y te pedirá que uses Source Generators (generadores de código en tiempo de compilación).
